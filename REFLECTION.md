# Reflection

The coding assistant helped most with early design work.
For this project, that meant brainstorming the agent flow, comparing frameworks, checking library docs, and turning a loose idea into a small runnable shape.
That stage requires reading a lot of APIs and tradeoffs, and the model was useful because it could digest that information quickly and help me narrow the options.

I ignored it more when defining tests and evaluation cases.
Those tests are the final guardrail for code quality, especially when some code is generated by an LLM.
I still used the assistant for syntax and small edits, but I wanted the actual cases to come from my own judgment: where the workflow is most likely to fail, where the agent may choose the wrong tool, and where the answer may look plausible without enough evidence.

Using an agent to write an agent did not feel recursive in a strange way.
The work still came down to the same questions as production code: what context the model receives, what tools it can call, what contract the output must satisfy, and how failures are handled.
It was useful for prompt work because the target model often has a better feel for instructions it can follow.
Writing prompts with the same model family I intend to run can improve how well the final agent follows those instructions.

For traceability and observability, I think about two layers.
At the agent layer, I want chronological logs and traces that show which tool was called, what evidence came back, and why the agent moved to the next step.
At the codebase layer, the strategy is to keep AI-assisted changes small.
A large plan should be broken into narrow, actionable changes that can be reviewed, tested, and traced one by one.
That also helps the model, because smaller tasks need less context and usually produce better code.

My reliability strategy starts with a minimum viable prototype that proves the core workflow works.
After that, I add features only when I can measure them with evaluations.
For this project, the important metrics are whether the agent chooses the right first tool, falls back when evidence is weak, grounds the answer in retrieved evidence, and produces a trace that explains the path it took.
